# SKYSTRIKE // ACE PROTOCOL

Arcade jet combat game. Three.js (r159, vendored), single HTML page, no build step, no framework, no modules.

**Source of truth: GitHub `timbleslu/skystrike`, worked via this clone. `git fetch`/`pull` before editing. Ignore any Obsidian Vault or `~/Downloads` copy of Skystrike — they are stale decoys, never source.**

## Run / Test
- Play: open `index.html` in a browser (or any static server).
- Mobile motion test: `npm run serve:https` — LAN HTTPS static server (self-signed cert; accept the warning on the phone). DeviceOrientation needs a secure context, so `file://` / plain http yields zero events.
- Tests: `npm test` — plain Node scripts in `tests/*.test.js`, no test framework. Pure cores live in `js/core.js` and are `require()`d directly by tests (one source of truth — no byte-identical mirror copies). A few legacy tests that read non-require-safe files (e.g. `entities.js` airframes, `ground-war` reqSatisfied) still mirror or `readFileSync`-extract; new pure logic should go in `core.js` and be imported.
- Visual check: `node scripts/shot.mjs <outPrefix> [tod 0|1|2]` — boots the game headless (playwright devDep) and saves hangar/flight/fx/terrain screenshots. Use this to verify any graphics change.
- Close-up check: `node scripts/beauty.mjs <outPrefix> [jetIndex] [tod]` — UI-hidden hangar close-ups (jet front/side/rear + missile/tracer ordnance board). Use when judging model/material quality.

## Architecture (read this, skip exploration)
All code is browser globals — no imports/exports. Script load order in `index.html` defines availability:
`vendor/three.min.js → vendor/GLTFLoader.js → storage.js → core.js → globals.js → i18n.js → engine.js → entities.js → rival.js → meta.js → opmap.js → missions.js → combat.js → hud.js → ui-hud.js → ui-tech.js → ui-hangar.js → ui-flow.js → ui-settings.js → controls.js → main.js`

**Pure-core seam (`js/core.js`):** all dependency-free game logic lives here, loaded FIRST. In the browser it defines plain globals like every other file; in Node it `module.exports`-es them (footer guarded by `typeof module`, inert in the browser) so `tests/*.test.js` `require('../js/core.js')` and exercise the REAL implementation. This replaced the old pattern where each test carried a byte-identical copy guarded by a string-equality assert. **Keep `core.js` pure — no THREE/store/DOM references, or it stops being require-safe.**

## Hard rules
- All new user-facing strings go through `t(key)` (static UI) or `jetText`/`techText` (JETS/TECH_TREE rows); add EN+ZH entries in `js/i18n.js`.
- No direct `localStorage` outside `js/storage.js` (test-enforced).
- No ES modules / `import` — globals only, respect load order. The ONLY sanctioned module syntax is a **CommonJS export footer** — `if (typeof module !== 'undefined' && module.exports) module.exports = {…}` — on require-safe files (`core.js`, plus footers on `opmap`/`missions`/`meta`/`rival`) so Node tests can `require()` the real implementation instead of carrying byte-identical copies. It is inert in the browser (`module` is undefined there). New pure logic should go in `core.js` and be imported by its test, NOT mirrored.
- Three.js is vendored; never re-add CDN script tags. r128-era API calls go through shims in `engine.js`.
- Geometry/materials may be shared via cache — use `disposeGroup` for cleanup; never dispose marker geometry. `disposeGroup` skips geometry AND materials tagged `userData.shared` (cached jet geometry, ASSET missile hull/trim/sprite mats) — tag anything new that multiple live objects share.
- Enemy death/despawn must call `clearLocks(e)` and remove marker.
- Custom `ShaderMaterial` fragment shaders must end with `#include <tonemapping_fragment>` + `#include <colorspace_fragment>` or they won't match the scene's ACES/sRGB grading.
